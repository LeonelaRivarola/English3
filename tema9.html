Arquitectura Cliente-Servidor

Introducción a Internet y la Arquitectura Cliente/Servidor

1. Arquitectura Cliente/Servidor:

  • Cliente: Inicia la comunicación.
  • Servidor: Siempre activo, esperando peticiones.
  • Múltiples clientes heterogéneos en cuanto a sistemas operativos, software y hardware.

2. Componentes clave de Internet

  • Cliente: Interfaz y navegación.
  • Servidor: Lógica de negocio, procesamiento de solicitudes.
  • Datos: Almacenamiento persistente en bases de datos.

3. Infraestructura de Red

  • Protocolo TCP/IP: Base de la comunicación en Internet.
  • HTTP: Protocolo principal para la web.
  • Capas de red y aplicaciones disponibles.

Problemas asociados a Internet

Sobre carga del servidor: Cuando un único servidor atiende demasiados clientes, el rendimiento del sistema decrece exponencialmente.

Arquitectura Cliente/Servidor en detalle

  • Capas del software:
    • Presentación: Clientes y su interfaz gráfica.
    • Lógica de negocio: Procesos y reglas implementadas en el servidor.
    • Persistencia: Gestión de datos mediante bases de datos.
  • Elementos de toda aplicación:
    • Presentación: Diseño de interfaces y experiencia de usuario.
    • Lógica: Procesos de negocio que gestionan las solicitudes del cliente.
    • Datos: Información almacenada en bases de datos.

** Arquitecturas **

Definición: Las arquitecturas definen cómo se estructuran los sistemas de software según sus capas o niveles.

Tipos principales:

  • Monolíticos (One Tier): Todo en un solo módulo.
  • Cliente/Servidor (Two Tier): Separación entre cliente y servidor.
  • Tres Capas (Three Tier): Presentación, lógica de negocio y datos en capas separadas.
  • N Capas (N Tier): División más fina en varias capas especializadas.

Las arquitecturas evolucionaron desde sistemas monolíticos simples hacia modelos distribuidos complejos para resolver problemas de escalabilidad, mantenimiento y usabilidad. La elección de una arquitectura depende del contexto del sistema, necesidades de escalabilidad, flexibilidad y costos.

1. Sistemas Monolíticos (Una Capa)

  • Características: Todo (datos, lógica de negocio, presentación) en un solo módulo.
  • Desventajas:
    • Difícil identificar cambios.
    • Problemas de rendimiento y escalabilidad.
    • Baja reutilización de código.

2. Arquitectura Cliente/Servidor (Dos Capas)

  • Características:
    • Cliente realiza la interfaz de usuario.
    • Servidor gestiona datos y lógica de negocio.
    • Tipos de cliente: Cliente pesado (fat client), Cliente liviano (thin client).
  • Ventajas:
    • Mejor escalabilidad y flexibilidad.
    • Datos centralizados evitan duplicaciones.
  • Desventajas:
    • Puede generar alto tráfico de red.
    • Aplicaciones cliente tienden a ser monolíticas.
    • Dificultad para reutilizar código y escalar.

3. Arquitectura de Tres Capas (Three Tier)

  • Características:
    • Separación lógica y física de: Presentación, Negocio, Datos.
    • Introduce una capa intermedia (Middle Tier Server) para reglas de negocio.
    • Facilita mantenimiento, escalabilidad y reusabilidad.
  • Usos comunes:
    • Aplicaciones en internet.
    • Sistemas distribuidos.
  • Desventajas:
    • Construcción más compleja.
    • Herramientas de desarrollo limitadas en ocasiones.

4. Arquitectura de N Capas (N Tier)

  • Características:
    • Divisiones más específicas: acceso a datos, reglas de negocio, lógica de presentación.
    • Ejemplo de capas:
      • Capa de Datos: Gestión de la base de datos (MySQL, Oracle, etc.).
      • Capa de Acceso a Datos: Métodos para interactuar con la base de datos (ej. JDBC).
      • Capa de Negocio: Regla de negocio y manipulación de datos.
      • Capa de Presentación: Interacción con el usuario.
  • Ventajas:
    • Adaptabilidad a entornos distribuidos.
    • Facilita el uso de tecnologías modernas.
